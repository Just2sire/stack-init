# How to Scaffold an Express TypeScript REST API

Writing an Express + TypeScript REST API from scratch means creating the same files every time: a server entry point, route files, controller classes, service layers, Prisma models, input validation, and Swagger annotations. StackInit generates the entire structure in under two minutes.

This guide walks through scaffolding a **production-ready Express TypeScript API** with Prisma ORM, service/repository architecture, and Swagger docs — using a real-world example: an e-commerce backend with Products, Categories, Orders, and Users.

---

## Prerequisites

- Node.js 18+ and pnpm
- A PostgreSQL or SQLite database
- Familiarity with Express.js and TypeScript basics

---

## Step 1 — Pick Express in StackInit

Open [StackInit](/create) and select **Express** as your stack. Under **Options**, choose:

- **TypeScript** — yes (always recommended)
- **ORM** — Prisma
- **Architecture** — Service layer (Controller → Service → Prisma)
- **Validation** — Zod

---

## Step 2 — Define your data models

In the **Models** step, add your entities:

- **User** — `name: string`, `email: string (unique)`, `passwordHash: string`, `role: enum(customer, admin)`
- **Category** — `name: string`, `slug: string (unique)`
- **Product** — `name: string`, `price: decimal`, `stock: integer (default: 0)`, `description: text (nullable)`
- **Order** — `total: decimal`, `status: enum(pending, paid, shipped, cancelled)`, `createdAt: timestamp`

---

## Step 3 — Set up relations

- `Product` **belongsTo** `Category`
- `Order` **belongsToMany** `Product` (pivot: `order_items` with `quantity: integer`, `unitPrice: decimal`)
- `Order` **belongsTo** `User`

The pivot table fields (`quantity`, `unitPrice`) can be added directly in StackInit's relation editor.

## Running the project

```bash
pnpm install

# Configure your database
cp .env.example .env
# Edit .env: DATABASE_URL="postgresql://..."

# Run migrations
pnpm prisma migrate dev --name init

# Start dev server (ts-node-dev)
pnpm dev
```

The API starts on `http://localhost:3000`. Swagger UI is available at `http://localhost:3000/api-docs`.

## Example: a generated service

```typescript
// src/services/ProductService.ts
import { prisma } from "../lib/prisma";
import { CreateProductInput } from "../schemas/product.schema";

export class ProductService {
  async findAll() {
    return prisma.product.findMany({ include: { category: true } });
  }

  async create(data: CreateProductInput) {
    return prisma.product.create({ data });
  }

  async update(id: string, data: Partial<CreateProductInput>) {
    return prisma.product.update({ where: { id }, data });
  }

  async delete(id: string) {
    return prisma.product.delete({ where: { id } });
  }
}
```

Every service is generated with your actual field names, your Prisma relations, and your validation schema — not Lorem Ipsum placeholders.
